# История для каталога: от замысла до телефона

## Когда работа завершена

Просьба создать готовую историю для каталога включает публикацию. Исключение —
явная просьба оставить черновик или отложить публикацию. На этапе обсуждения
идеи и незавершённого написания публиковать нечего.

Локальная карточка, коммит и push — промежуточные этапы. Готовность подтверждают
успешный GitHub Pages deployment **и проверка публичных файлов**. В итоговом
ответе должны быть рабочая публичная ссылка, результаты проверки и точный
статус. Если публикация не прошла, работа ещё не завершена.

## Создание

1. Найти выбранный замысел в истории чата. Подготовить мир, героиню, второго
   главного героя, самостоятельных второстепенных персонажей, приключенческие
   этапы, развитие отношений, тайны и развязки. Оставить решения и чувства
   игроку. Автор административных историй — «Администрация».
2. Сохранить игровые Markdown-модули и JPEG в
   `public/templates/STORY_ID/rN/`. Соблюдать [TEMPLATE_FORMAT.md](TEMPLATE_FORMAT.md):
   до 12 000 символов на модуль, **до 60 000 вместе с заголовками сборки**.
   Пересчитать SHA-256, проверить роли, пути, реальные размеры картинок.
3. Создать все иллюстрации встроенным генератором. Чёткая композиция и понятные
   формы; избегать **high frequency artificial detail**, микротекстур, шума и
   перешарпа. Просмотреть каждое изображение. Оригиналы — в игнорируемом `data/`,
   на сайте — нормализованные JPEG и генерируемые WebP.
4. Досье со структурой и разгадками, а также точные запросы для изображений — в
   `story-notes/`. Публичные описания карточек должны помогать выбрать историю.
   Зарегистрировать пакет в `public/templates/index.json`; индексы
   `catalog.json` и `browse.json` генерируются сборщиком.

## Проверка и публикация

1. Выполнить в репозитории каталога `npm test` и `npm run build`. Проверить
   реальный импорт пакета ботом в отдельной синтетической БД: анкеты, портреты,
   снимок версии, ограничения текста и сохранность прежней игры. Не использовать
   рабочую БД и не запускать платную генерацию для проверки импорта.
   Из корня проекта бота:
   `.venv/Scripts/python.exe scripts/verify_catalog_import.py --public catalog/public`.
2. Просмотреть карточку и диалоги модулей в браузере, в том числе на узком экране.
   Проверить вход с синтетическим фрагментом Telegram, например
   `#tgWebAppVersion=9.1&tgWebAppPlatform=android`: должна открыться главная
   страница каталога. Проверить обычную ссылку `#/stories/STORY_ID` и ссылку на
   отсутствующую историю. Использовать только искусственные launch-параметры.
3. Просмотреть diff. Коммитить и пушить только нужные файлы репозитория каталога;
   не включать соседние черновики, базы, секреты или чужие изменения. Дождаться
   завершения workflow `pages.yml` для нужного коммита. В workflow уже включена
   проверка опубликованного сайта.
4. Дополнительно выполнить локально:

   ```powershell
   npm run verify:published -- --url https://miroschnikovvladimir.github.io/SimpleDeepseekCatalog/
   ```

   Команда сравнивает ожидаемый commit с `release.json`, полный и облегчённый
   индексы, все зарегистрированные manifest/Markdown/JPEG/WebP, HTML, SDK и
   собранные JS/CSS. Проверяется содержимое по SHA-256, а не только HTTP 200.
   Ошибка означает, что публикацию пока нельзя считать завершённой.
   Проверить настоящий импорт с публичного адреса из корня проекта бота:
   `.venv/Scripts/python.exe scripts/verify_catalog_import.py --url https://miroschnikovvladimir.github.io/SimpleDeepseekCatalog/`.
5. Просмотреть **публичный** сайт в браузере с входом Telegram и карточками новых
   историй. Указать в досье публичную ссылку и проверенный статус. Пользователю
   дать публичные ссылки, а не `localhost`.

## Изменения Mini App и бота

При изменении интерфейса проверить маршруты, старт SDK, открытие карточек и
обычные ссылки. Официальный SDK хранится без изменений в `public/vendor/`, чтобы
страница не зависела от отдельного блокирующего запроса к telegram.org.
`browse.json` содержит тексты для чтения карточек; `catalog.json` сохраняет полный
контракт импорта для бота. Индексы компилируются вместе, из одного источника.

После изменения интерфейса, требующего обхода кеша старого Mini App, обновить
`CATALOG_APP_VERSION` в `botapp/catalog.py`. Параметр версии добавляется только к
URL кнопки; адрес загрузки пакетов остаётся чистым. Клавиатура с этой кнопкой —
`one_time_keyboard=False`, `is_persistent=False`: она не прячется при нажатии,
но пользователь может скрыть её сам.

Изменения основного бота применяются через навык `simpledeepseekbot-restart`
после тестов и проверки незавершённой работы. Изменения историй и статического
сайта сами по себе перезапуска бота не требуют. Отдельный image bot не трогать.
