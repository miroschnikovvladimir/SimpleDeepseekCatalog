## Назначение

Это каталог игровых заготовок для Telegram Mini App: история состоит из
сеттинга, сюжета и персонажей. Он позволяет выбрать готовую историю или
собрать свою из сохранённых частей и передать выбор боту.
В статическом `public/catalog.json` — 5 историй и 26 модулей, формат версии 2.

## Устройство

- `src/App.tsx`: карточки, поиск по названию/описанию/тегам/категориям,
  фильтр категорий, детали истории, избранное, конструктор и отправка материалов.
- `src/types.ts`: `Story`, `StoryModule`, изображения и авторы.
- `src/api.ts`: сначала получает каталог через API, при ошибке читает
  статический `catalog.json`. Избранное без настроенного API хранится локально.
- React 19, TypeScript, Vite 7, pnpm. Маршрутизация через URL hash.
- `.github/workflows/pages.yml`: push в `master` запускает установку зависимостей,
  тесты, сборку и публикацию `dist` в GitHub Pages.
- `vite.config.ts`: базовый путь `/Catalog/`, который нужно заменить для нового сайта.
- `api/worker.ts`: Hono API в Cloudflare Worker; база D1 и изображения R2.
- `api/auth.ts`: проверка Telegram initData и подписанные сессии.
- API обслуживает избранное, заявки на импорт, загрузку изображений,
  пользовательские материалы и модерацию.

## Связь с ботом

Готовая история передаёт через `Telegram.WebApp.sendData`:
`{ "action": "import", "story_id": "..." }`.

Конструктор создаёт заявку в API и передаёт:
`{ "action": "import_request", "import_id": "..." }`.

Бот должен получить соответствующий материал по доверенному источнику,
проверить владельца заявки, создать историю и отметить импорт завершённым.
В текущем SimpleDeepseekBot обработчиков этих событий и открытия Mini App нет.
Его существующий экспорт TXT/HTML/MD выгружает сыгранный текст; это другой
формат, чем игровые заготовки каталога.

## Что понадобится для адаптации

1. Определить состав нового каталога и имя нового репозитория.
2. Адаптировать интерфейс и формат заготовок под текущую модель бота.
3. Добавить в бота открытие Mini App и проверяемый импорт выбранной истории.
4. Если нужны серверные функции, создать отдельные Worker/D1/R2 и секреты.
   Адрес API и идентификаторы ресурсов старого проекта автоматически не переносить.
5. Настроить GitHub Pages для нового репозитория и его базового пути.

README старого каталога ссылается на подробную инструкцию в приватном
репозитории другого проекта; эта инструкция не была доступна при разборе.
Локальные медиа, базы и ключи текущего бота в новый каталог не копировались.
